# Первая 360-новелла: пошаговое руководство

Это руководство рассчитано на студента, который впервые открыл проект и раньше
не работал ни с движком, ни с 360-панорамами.

В результате получится небольшая новелла:

1. сначала игрок увидит обычную сцену с картинкой и поясняющим текстом;
2. затем войдёт в 360-пространство;
3. сможет перейти между двумя панорамами;
4. откроет фотогалерею внутри панорамы;
5. вернётся из 360-пространства в обычную сцену.

Для первого раза лучше повторить пример буквально. Когда он заработает, можно
заменить изображения, названия и текст своими.

---

## 1. Что где хранится

В 360-новелле используются три разных вида файлов:

| Файл | Для чего нужен |
| --- | --- |
| `story.js` | Обычные сцены, текст, вступление и команда входа в 360 |
| `story360.js` | Карта 360-пространства: панорамы, метки, фокусы и переходы |
| `*-360.css` | Само панорамное изображение, упакованное для автономной загрузки |

Обычную картинку вступления и изображения фотогалереи можно хранить как
`JPEG`, `PNG` или `WebP`. В CSS нужно преобразовывать только изображения,
которые используются как WebGL-панорамы.

Рекомендуемая структура учебного проекта:

```text
project/
├── index.html
├── story.js
├── story360.js
├── assets/
│   ├── backgrounds/
│   │   └── intro.webp
│   ├── 360/
│   │   └── Campus/
│   │       ├── P1-360.css
│   │       ├── P1-360-mobile.css
│   │       ├── P2-360.css
│   │       └── P2-360-mobile.css
│   └── gallery/
│       ├── exhibit1.webp
│       └── exhibit2.webp
└── tools/
    ├── convert-360-img-to-css.html
    └── scene360-editor.html
```

Все пути в сценарии и редакторе указываются относительно папки проекта. Нужно
использовать прямые слеши `/`, например:

```text
assets/360/Campus/P1-360.css
```

Не используйте путь с буквой диска, `file:///`, обратные слеши или выход из
проекта через `..`.

## 2. Основные понятия

| Понятие | Простое объяснение |
| --- | --- |
| Пространство | Группа связанных панорам, например весь корпус или музей |
| Панорама | Одна точка обзора внутри пространства |
| Метка | Интерактивная точка: переход, выход, обзор или фотогалерея |
| Фокус | Направление, куда смотрит камера сразу после входа |
| `default` | Базовый фокус панорамы |
| Сценарный вход | Отдельный фокус для входа из обычной сцены через `from=...` |

В этом примере пространство называется `Campus`, а две панорамы — `P1` и
`P2`. Вместе они записываются как `Campus.P1` и `Campus.P2`.

ID пространства, панорамы и метки в редакторе могут содержать только латинские
буквы `A-Z`, `a-z` и цифры `0-9`. Примеры правильных ID:

```text
Campus
P1
toP2
gallery1
```

Пробелы, кириллица, дефисы и подчёркивания в этих ID не используются. В именах
файлов дефисы и подчёркивания допустимы.

## 3. Шаг 1. Сделайте обычное вступление

Начинать новеллу сразу с панорамы не рекомендуется. Обычная вступительная сцена
помогает игроку понять тему, управление и цель исследования.

Подготовьте обычное изображение `assets/backgrounds/intro.webp`. Это не
панорама, поэтому преобразовывать его в CSS не нужно.

Создайте в корне проекта файл `story.js`:

```js
window.STORY_TEXT = `

[meta]
title = "Первая 360-новелла"
projectId = student360demo
startScene = intro
lang = ru
mode = release
window = auto
autosave = true
transition = fade
transitionMs = 180
bg360Quality = auto
engine.gameSandbox = strict

[bg]
introBg file=assets/backgrounds/intro.webp

[scene]
scene intro
bg introBg
"Добро пожаловать в виртуальную экскурсию."
"Внутри панорамы поворачивайте камеру мышью или пальцем."
"Нажимайте на стрелки, метки и изображения, чтобы исследовать пространство."
goto360 Campus.P1 from=intro text="Осмотрите учебное пространство" button="Продолжить историю"
goto after360

scene after360
bg introBg
"Экскурсия завершена."
"Теперь можно продолжить обычную часть новеллы."
`;
```

Что делает этот сценарий:

- `bg introBg` показывает обычную вступительную картинку;
- строки в кавычках показывают поясняющий текст;
- `goto360 Campus.P1` открывает первую панораму;
- `from=intro` выбирает отдельный фокус входа из сцены `intro`;
- `button="Продолжить историю"` оставляет игроку понятную кнопку выхода;
- после выхода выполняется `goto after360`;
- метка выхода из панорамы тоже сможет сразу открыть сцену `after360`.

Пока `story360.js` ещё не создан, переход в панораму не заработает. На этом
этапе достаточно проверить, что двойной клик по `index.html` показывает
вступительную картинку и текст.

## 4. Шаг 2. Подготовьте исходные панорамы

Для каждой точки обзора нужен эквидистантный панорамный кадр с соотношением
сторон `2:1`.

Примеры размеров:

| Условное качество | Размер кадра при точном 2:1 |
| --- | --- |
| Mobile 1080 | `2160 × 1080` |
| Mobile 1440 | `2880 × 1440` |
| 4K | `3840 × 1920` |
| 5.7K | `5760 × 2880` |
| 8K | `7680 × 3840` |

Перед конвертацией проверьте:

- ширина примерно в два раза больше высоты;
- горизонт не наклонён;
- левый и правый края изображения сшиваются без заметного разрыва;
- сверху и снизу нет крупных ошибок склейки;
- изображение открывается в обычном просмотрщике;
- имя файла короткое и понятное, например `P1.jpg` и `P2.jpg`.

Сохраните исходные панорамы отдельно. Для запуска новеллы понадобятся созданные
CSS-пакеты, но исходники пригодятся, если позже потребуется другое разрешение
или качество.

## 5. Шаг 3. Преобразуйте панорамы в CSS

Откройте двойным кликом:

```text
tools/convert-360-img-to-css.html
```

Для первой панорамы выполните следующие действия:

1. В поле «Формат сохраняемых пакетов» выберите `CSS — безопасный`.
2. На вкладке «Одиночная обработка» выберите исходный `P1.jpg`, `P1.png` или
   `P1.webp`.
3. Настройте варианты `Normal` и `Mobile`.
4. Нажмите «Сгенерировать normal + mobile».
5. Проверьте превью, итоговые размеры и предупреждения.
6. Нажмите «Скачать оба CSS».

Для первого проекта можно начать с таких настроек:

| Вариант | Высота | Качество | Формат |
| --- | ---: | ---: | --- |
| Normal | `1920 (4K)` | `85` | `WebP` |
| Mobile | `1080` или `1440` | `75` | `WebP` |

Это стартовая рекомендация, а не обязательное правило. `2880 (5.7K)` и
`3840 (8K)` дают больше деталей, но создают более тяжёлые файлы и требуют больше
памяти. Для телефонов сначала используйте Mobile 1080 или 1440 и обязательно
проверяйте результат на реальном устройстве.

Конвертер создаст файлы:

```text
P1-360.css
P1-360-mobile.css
```

Переместите их в:

```text
assets/360/Campus/
```

Повторите те же действия для `P2`.

В `story360.js` указывается только основной путь `P1-360.css`. При
`bg360Quality = auto` движок сам выберет `P1-360-mobile.css` на уверенно
определённом телефоне. Поэтому имена Normal и Mobile должны отличаться только
суффиксом `-mobile`.

Если панорам много, используйте вкладку «Пакетная обработка»:

1. выберите несколько исходных изображений;
2. отметьте `normal` и `mobile`;
3. проверьте общие настройки;
4. нажмите «Пакетно преобразовать и скачать»;
5. дождитесь завершения очереди и разложите файлы по папкам проекта.

### Почему нельзя просто указать `P1.jpg`

При автономном запуске через `file://` браузер может показать локальное
изображение как обычную картинку, но запретить передать его в WebGL-текстуру.
Результатом будет ошибка безопасности или чёрная панорама. CSS-пакет позволяет
автоматически загрузить изображение после обновления страницы, проверить его и
безопасно передать данные в WebGL.

CSS-пакет уже содержит изображение в base64. Не редактируйте его вручную и не
добавляйте в него свои стили, `url()` или `@import`.

JS в списке форматов оставлен только для старых доверенных проектов. Для новой
новеллы выбирайте CSS.

## 6. Шаг 4. Создайте первую панораму в редакторе

Откройте:

```text
tools/scene360-editor.html
```

Для первой панорамы заполните:

| Поле | Значение примера |
| --- | --- |
| ID пространства | `Campus` |
| ID панорамы | `P1` |
| Путь CSS-пакета | `assets/360/Campus/P1-360.css` |

Нажмите «Загрузить превью по пути». В правой части должна появиться панорама.
Проверьте, что её можно поворачивать мышью или пальцем.

Если вместо изображения появился чёрный фон, сначала проверьте:

- существует ли файл по указанному пути;
- совпадает ли регистр букв в папках и имени файла;
- заканчивается ли путь на `-360.css`;
- не указан ли исходный `JPG`, `PNG` или `WebP`;
- создан ли пакет текущим конвертером.

После успешной загрузки нажмите «Сохранить панораму».

## 7. Шаг 5. Настройте базовый фокус

Базовый фокус `default` — это направление камеры, которое используется, когда
для конкретного входа не задан отдельный ракурс.

Для настройки:

1. поверните панораму так, чтобы в центре находился главный объект;
2. во время поворота значения `focusX` и `focusY` обновятся;
3. нажмите «Применить focus»;
4. нажмите «Сохранить панораму».

Не нужно вычислять `focusX` и `focusY` вручную. Оба значения находятся в
диапазоне от `0` до `1`.

Для первой панорамы полезно направить камеру на понятную точку начала маршрута:
дверь, стенд, вывеску или центральный объект.

---

## 8. Шаг 6. Добавьте вторую панораму

Нажмите «Новая панорама». Редактор создаёт копию текущей панорамы, поэтому
обязательно замените её данные:

1. укажите ID `P2`;
2. укажите путь `assets/360/Campus/P2-360.css`;
3. нажмите «Загрузить превью по пути»;
4. удалите или измените скопированные метки, если они уже были;
5. настройте базовый фокус;
6. нажмите «Сохранить панораму».

Переключаться между сохранёнными панорамами можно через список «Панорамы в
текущем файле».

Для первого проекта лучше сначала создать и проверить все панорамы, а затем
добавлять переходы. Тогда редактор сразу сможет определить, существует ли цель
каждой метки.

## 9. Шаг 7. Расставьте метки

Чтобы поставить метку:

1. откройте нужную панораму;
2. выберите тип в разделе «Новая метка»;
3. поверните камеру так, чтобы нужное место оказалось в центре прицела;
4. нажмите «Поставить метку»;
5. настройте появившуюся карточку в «Списке меток».

Основные типы:

| Тип | Для чего использовать |
| --- | --- |
| `walk` | Основной переход: стрелка направления и пункт на компасе |
| `text` | Компактная экранная точка без напольной стрелки |
| `view` | Направление обзора на компасе без напольной стрелки |
| `photo` | Превью, открывающее одно изображение или галерею |

Для первого проекта достаточно типов `walk` и `photo`.

В карточке обычной метки задаются:

- `text для компаса` — понятная игроку подпись, например `В коридор`;
- ID метки — техническое уникальное имя, например `toP2`;
- тип метки;
- `visibleIf` — необязательное условие видимости;
- тип перехода и его цель.

Поле `visibleIf` в первом проекте оставьте пустым. Позже в нём можно указать
условие из переменных сценария, например `doorOpened && !alarmOn`.

### Переход в другую панораму того же пространства

На панораме `Campus.P1` создайте метку:

```text
ID: toP2
text: В следующую аудиторию
type: walk
переход: В 360-панораму
цель: P2
```

Если в цели нет точки, редактор использует текущее пространство. Поэтому `P2`
означает `Campus.P2`.

### Переход в другое пространство

Формат цели:

```text
Space.Panorama
```

Например:

```text
BuildingB.P2
```

До точки указано пространство, после точки — панорама. Точка может быть только
одна. При таком переходе текущее пространство полностью игнорируется.

Для первой учебной новеллы удобнее держать связанный маршрут в одном
пространстве и использовать короткие цели `P1`, `P2`, `P3`.

### Выход в обычную сцену

На панораме `Campus.P2` создайте метку:

```text
ID: exitTour
text: Завершить экскурсию
type: walk
переход: В обычную сцену
цель: after360
```

После нажатия игрок сразу перейдёт к `scene after360` из `story.js`.

Кнопка «Перейти» в карточке позволяет проверить 360-переход прямо в редакторе.
После настройки каждой панорамы нажимайте «Сохранить панораму».

## 10. Шаг 8. Настройте разные фокусы входа

Одна панорама может открываться с разных сторон. Например, при переходе из
`P1` в `P2` игрок должен смотреть назад, а при входе из обычной сцены — на
главный стенд.

В `entries` для этого хранятся отдельные фокусы:

```text
default   — базовый вход
intro     — вход из обычной сцены intro
P1        — вход после перехода с панорамы P1
```

### Фокус входа из обычной сцены

В `story.js` уже используется:

```text
goto360 Campus.P1 from=intro
```

Чтобы создать соответствующий фокус:

1. откройте `Campus.P1`;
2. поверните камеру в нужную сторону;
3. в поле «Сценарный вход from=&lt;sceneId&gt;» укажите `intro`;
4. нажмите «Записать из камеры»;
5. убедитесь, что в списке фокусов появился `from=intro (сцена)`;
6. сохраните панораму.

Значение после `from=` должно точно совпадать с ключом в редакторе. Если в
сценарии написано `from=intro`, нельзя назвать вход `fromIntro`.

### Фокус перехода между панорамами

Сначала сохраните метку `P1 → P2`. Затем откройте `P2`. Редактор создаст для
неё вход с ключом `P1`.

На панораме появится прицел с подписью `P1` или `С «P1»`. Перетащите этот прицел
на направление, куда должна смотреть камера после прихода из `P1`, затем
сохраните панораму.

Для обратного направления:

1. создайте и сохраните метку `P2 → P1`;
2. откройте `P1`;
3. настройте появившийся фокус `P2`;
4. сохраните панораму.

Кнопка `Y→½` возле фокуса выравнивает его по середине панорамы. Это удобно,
если камера после входа смотрит слишком высоко или слишком низко.

Проверяйте фокус кнопкой «Перейти» у исходной метки. Важно оценить результат
именно как переход, а не только открыть целевую панораму из общего списка.

## 11. Шаг 9. Добавьте фотогалерею в панораму

Изображения галереи не являются панорамными текстурами. Их не нужно
преобразовывать в CSS.

Скопируйте обычные изображения в проект:

```text
assets/gallery/exhibit1.webp
assets/gallery/exhibit2.webp
```

В редакторе:

1. выберите тип новой метки `photo`;
2. поверните камеру к объекту, рядом с которым должна быть галерея;
3. нажмите «Поставить метку»;
4. задайте ID, например `gallery1`;
5. в поле `Название на сцене (label)` напишите `Материалы стенда`;
6. для первого фото укажите путь и подпись;
7. нажмите `+ Добавить фото` и добавьте остальные изображения;
8. кнопками `↑` и `↓` задайте порядок;
9. сохраните панораму.

Пример заполнения:

```text
Фото 1
file: assets/gallery/exhibit1.webp
caption: Общий вид экспоната

Фото 2
file: assets/gallery/exhibit2.webp
caption: Деталь конструкции
```

В игре рядом с объектом появится превью. Если изображений несколько, будет
показано их количество. Нажатие открывает просмотрщик, в котором изображения
можно листать; `caption` показывается под соответствующим кадром.

Разница между подписями:

- `label` — название всей фотометки рядом с превью в панораме;
- `caption` — подпись конкретного изображения внутри просмотрщика;
- `text для компаса` — подпись направления, обычно для photo её можно оставить
  пустой.

Большие изображения галереи тоже расходуют память и дольше загружаются. Перед
добавлением уменьшите их до разумного размера и проверьте на телефоне.

## 12. Шаг 10. Сохраните `story360.js`

В редакторе есть два разных действия:

- «Сохранить» сохраняет рабочий черновик в Local браузера;
- «Скачать story360.js» создаёт файл, который нужен самой новелле.

Локальный черновик удобен для продолжения работы, но не заменяет файл проекта.

В конце работы:

1. сохраните текущую панораму;
2. нажмите «Скачать story360.js»;
3. переместите скачанный файл в корень проекта рядом с `story.js`;
4. убедитесь, что имя файла ровно `story360.js`;
5. если браузер создал `story360 (1).js`, переименуйте файл;
6. при следующем редактировании загрузите актуальный `story360.js` через поле в
   верхней части редактора.

`index.html` подключает `story360.js` автоматически. Добавлять отдельный тег
`script` не нужно.

## 14. Полная проверка проекта

Закройте редактор и запустите новеллу через `index.html` как обычный
пользователь.

Проверьте по порядку:

1. показывается вступительная картинка;
2. поясняющий текст читается и не закрывает важную часть фона;
3. команда `goto360` открывает `Campus.P1`;
4. при входе камера смотрит в направлении `from=intro`;
5. панорама поворачивается мышью и пальцем;
6. метка `toP2` открывает `P2`;
7. камера в `P2` использует фокус прихода из `P1`;
8. обратная метка возвращает в `P1` с правильным ракурсом;
9. photo-метка открывает галерею;
10. изображения галереи листаются, подписи совпадают;
11. метка выхода открывает `after360`;
12. кнопка выхода из 360 тоже продолжает сценарий;
13. после обновления страницы панорамы загружаются без повторного выбора файлов;
14. на телефоне используется Mobile-пакет и проект не закрывается из-за нехватки
    памяти.

После этого откройте в редакторе «Массовые операции и отчёт целостности» и
сформируйте отчёт для всего файла. Исправьте отсутствующие цели переходов и
устаревшие фокусы.

## 15. Типичные ошибки

| Проблема | Что проверить |
| --- | --- |
| Чёрный фон в редакторе | Путь, имя `*-360.css`, регистр букв и наличие файла |
| Редактор сообщает о legacy JS | В `story360.js` остался путь `*-360.js`; замените его CSS-пакетом |
| Панорама искажена | Исходник должен быть эквидистантным и иметь соотношение `2:1` |
| На телефоне долго загружается | Уменьшите Mobile до 1080/1440 и качество до 75 |
| Переход подсвечен как отсутствующий | Сначала создайте и сохраните целевую панораму |
| `P2` ищется не там | Без точки используется текущее пространство; для другого укажите `Space.P2` |
| Переход `A.B.C` не работает | Допускается только одна точка: `Space.Panorama` |
| При входе неверный ракурс | Проверьте точное совпадение `from=intro` и ключа сценарного входа |
| Возврат смотрит не туда | Настройте entry с ID панорамы-источника, например `P1` |
| Галерея пустая | Проверьте пути `images[].file`; для галереи нужен обычный растровый файл |
| После скачивания изменения пропали | Замените корневой `story360.js` последней скачанной версией |
| После F5 работает старый вариант | Проверьте, какой `story360.js` лежит рядом с `story.js`, и обновите страницу |

Если требуется дополнительная диагностика 360, можно запустить проект с
параметром:

```text
index.html?Debug=360
```

Сообщения появятся в консоли разработчика браузера.
