# 🎬 VN Engine — Спецификация сценариев

Документ описывает язык сценариев для VN Engine.

Он нужен для:
- написания сценариев вручную
- генерации сценариев через ИИ
- проверки совместимости сценария с движком

Документ описывает:
- структуру файла `story.js`
- секции сценария
- команды сцен
- переменные и логику ветвления
- 360-фоны и отдельный файл `story360.js`
- вызов мини-игр из сценария

---

## 📌 Общая идея

Сценарий хранится в `story.js` как текстовый блок:

```js
window.STORY_TEXT = `
...содержимое сценария...
`;
```

`index.html` не выполняет этот файл в основном окне. Короткоживущий Web Worker
импортирует `story.js`, возвращает только строку `window.STORY_TEXT` и
завершается до запуска парсера. Поэтому штатный формат и свобода редактирования
сохраняются, а код файла не получает DOM и `localStorage` основной страницы.
Если `story.js` отсутствует, таким же способом загружается `story-example.js`;
повреждённый существующий файл демонстрационным примером не маскируется.

Сценарий состоит из секций и сцен.

Секции описывают:
- метаданные
- ресурсы
- переменные
- список сцен

Сцены описывают:
- показ фона и 360-пространств
- показ персонажей
- диалоги
- выборы
- переходы
- вызов мини-игр

## 📁 Общая структура сценария

Поддерживаются следующие секции:

- `[meta]` — метаданные сценария
- `[bg]` — фоновые изображения и 360-панорамы
- `[char]` — персонажи и их состояния
- `[audio]` — аудио-ресурсы
- `[video]` — сюжетные видео-вставки
- `[game]` — реестр мини-игр
- `[var]` — переменные сценария
- `[scene]` — сцены и команды

Минимальный пример:

```text
[meta]
title = "Demo Story"
projectId = demo-story
startScene = intro
engine.gameSandbox = strict
lang = en
mode = release
autosave = true
transition = fade
transitionMs = 180

[bg]
hall file=assets/backgrounds/bg_hall.jpg scroll focusx=0.5

[char]
anna emotion=neutral file=assets/characters/anna.png name="Анна" color=#0F0

[var]
resultGame = 0

[game]
coffeeRush file=assets/games/coffee_rush.html

[scene]
scene intro
bg hall
show anna neutral
anna: "Привет!"
```

## 🔧 Общие правила синтаксиса

- Рекомендуемый формат метаданных — `key = value`
- Идентификаторы (`sceneId`, `bgId`, `charId`, эмоции, `audioId`, `videoId`,
  `gameId`, пространства и входы story360) могут содержать
  только английские буквы, цифры и `_`; цифра в начале допустима
- Один и тот же идентификатор должен использоваться последовательно во всём сценарии
- Пустые строки допустимы
- Комментарии допустимы
- Сценарий должен быть читаемым и человеком, и ИИ

Раздел `IDENTIFIERS` в текстовой статистике проверяет объявления и ссылки на
такие идентификаторы и показывает места с другими символами. Проверка не
переименовывает старые проекты и не меняет поведение сценария. Пути к ресурсам
не являются идентификаторами: имена файлов и папок проверяются отдельно в
`FILE CHECK`. Идентификаторы панорам при объявлении и идентификаторы меток
story360 в эту проверку не входят. Целевая панорама, явно указанная в команде
`goto360`, проверяется по общему правилу.

`FILE CHECK` проверяет каждый каталог и имя файла в путях обычных ресурсов,
панорам story360 и изображений photo-меток. В каждом имени допустимы только
английские буквы, цифры, `-` и `_`; точка между именем файла и расширением
считается служебным разделителем.

Каждый путь авторского ресурса обязан быть каноническим относительным путём от
`index.html`: начинаться с `assets/` и использовать только прямой слеш `/`.
Внутри `assets/` разрешены произвольные подкаталоги. Запрещены URL со схемой,
сетевые и абсолютные пути, обратный слеш `\`, пустые компоненты, `.` и `..`,
query `?`, hash `#`, percent-encoding `%` и управляющие символы. Имена каталогов,
файлов и расширений используют английские буквы, цифры, `-` и `_`; файл должен
иметь расширение, допустимое для своей секции. Например,
`assets/img/scene.png` допустим, а `assets\img\scene.png`, `../scene.png` и
`https://example.test/scene.png` отклоняются парсером и повторно блокируются
движком в момент загрузки.

SVG разрешён только там, где ожидается изображение. Движок передаёт его в
пассивный контекст `<img>`/CSS-фона и не использует `iframe`, `object`, `embed`
или inline SVG. Для студенческого проекта аудитор отклоняет в SVG скрипты,
обработчики `on*`, `foreignObject`, внешние ссылки, активный CSS и заведомо
чрезмерную структуру.

В начале текстовой статистики после сведений о лицензии раздел `SUMMARY CHECK`
выводит одной строкой статусы парсинга, переменных, идентификаторов, файлов,
размеров изображений, CSS-панорам, сценария, условий story360, достижимости сцен
и циклов. Зелёная галочка означает отсутствие замечаний в соответствующем
разделе ниже, красный крестик — наличие, жёлтое предупреждение — невозможность
безопасной предварительной проверки без фактической загрузки ресурса.

Обычные растровые изображения входят в `FILE CHECK` и проверку размеров.
Семантически объявленные 360-изображения проверяются отдельно в
`360° PANORAMA PACKAGES` и обязаны ссылаться на `*-360.css`. После открытия
статистики выбранные с учётом `quality` normal/mobile-пакеты проходят ту же
строгую загрузку, проверку метаданных, Base64, бинарного заголовка и
декодирование, что и при реальном открытии панорамы. Пул ограничен четырьмя
пакетами на компьютере и двумя на телефоне. Это работает также через `file://`;
по HTTP(S) дополнительный `HEAD` используется только для точного статуса
`404`/`410`. Полоса показывает ход проверки. Закрытие окна её не отменяет, а в
сессионном кеше до F5 остаются только результат и небольшие метаданные без Blob
и полноразмерных изображений. Граф ресурсов по-прежнему показывает
полноразмерные панорамы и может заполнять тот же кеш, но при следующем открытии
графа изображение загружается заново. Необязательный `*-360-mobile.css` отдельно
не требуется, если выбран normal-вариант.

В представлениях полного графа и графа ресурсов используется отдельная полоса
загрузки. Она появляется на этапе подготовки Mermaid, затем считает каждый
штатно созданный движком элемент изображения: обычные фоны, изображения
персонажей, обложки игр и CSS-панорамы. Повторная асинхронная гидрация одной
CSS-панорамы не увеличивает общее число. После завершения полоса остаётся
видимой, показывает время и число ошибок. Это наблюдение не ограничивает
параллелизм загрузки графа.

Рекомендуется:
- использовать единый стиль именования
- не смешивать несколько стилей записи в одном файле
- держать сцены короткими и логически цельными

### Безопасность студенческих проектов

Перед проверкой и размещением студенческого проекта преподаватель копирует
содержимое актуального update-архива поверх проекта с заменой системных файлов.
Такое копирование не удаляет дополнительные файлы, поэтому итоговый каталог
проверяется через `tools/student-project-auditor.html` по инструкции
`docs/student-project-review.md`.

Для студенческого проекта `story.js` обязателен: fallback на
`story-example.js` не считается сданной историей. Из авторского JavaScript
допускаются только корневые `story.js` и необязательный `story360.js`, которые
движок загружает в отдельных Worker. Мини-игры предоставляются отдельными
зарегистрированными HTML-файлами со встроенными CSS и JavaScript и обязательным
строгим `meta Content-Security-Policy` из спецификации мини-игр.

Пакеты панорамных изображений `*-360.js` запрещены независимо от имени каталога
и суффикса. Поддерживаемый автономный формат панорамы — только `*-360.css`.
Корневой `story360.js` является декларативной картой 360-сцен и не относится к
пакетам изображений.

Файловый состав студенческого проекта проверяется по закрытому allowlist.
Системные файлы разрешены только по точным путям комплекта; в `assets/`
допускаются поддерживаемые медиаформаты, `*-360.css` и зарегистрированные
HTML-мини-игры, а в `docs/` — Markdown и растровые иллюстрации. Авторские и
справочные имена должны иметь ровно одно расширение. Серверные скрипты,
конфигурации, dotfiles, package/composer-манифесты, двойные расширения и все
неизвестные типы являются критической ошибкой аудитора. При размещении на VPS
проект копируется в чистый каталог и обслуживается только как статический,
без PHP, CGI и других исполняемых обработчиков.

## 🧾 Секция `[meta]`

Определяет общие параметры сценария.

Пример:

```text
[meta]
title = "Demo Story"
projectId = demo-story
startScene = intro
lang = en
mode = release
window = vertical
autosave = true
transition = fade
transitionMs = 180
bg360Quality = auto
engine.optimized = auto
engine.loadsafe = true
engine.gameSandbox = strict
```

Поддерживаемые поля:

### `title`

Название сценария. Рекомендуется заключать значение в двойные кавычки. Для
совместимости со старыми сценариями значение без кавычек также поддерживается.

```text
title = "Demo Story"
```

### `projectId`

Постоянный технический идентификатор проекта, который отделяет его
автосохранения от других новелл на том же origin:

```text
projectId = demo-story
```

Допустимы от 1 до 64 латинских букв, цифр и символов `.`, `_`, `-`; первый
символ должен быть буквой или цифрой. Регистр нормализуется в нижний, кавычки
необязательны. Значение должно быть уникальным среди проектов одного домена и
не должно меняться после публикации. Отображаемое название `title` можно менять
без переименования слота. При включённом `engine.loadsafe` любая правка текста
сценария всё равно может сделать текущее сохранение неподходящим для изменённой
версии истории.

Если `projectId` отсутствует, используется прежний общий ключ — это сохраняет
совместимость старых новелл при замене файлов движка. Новым проектам следует
всегда задавать собственный `projectId`.

### `startScene`

Идентификатор стартовой сцены.

```text
startScene = intro
```

Значение должно совпадать с существующей командой:

```text
scene intro
```

### `lang`

Язык интерфейса движка.

```text
lang = en
lang = ru
```

### `mode`

Режим исполнения истории.

```text
mode = debug
mode = release
```

`debug` используется по умолчанию и удобен при разработке: кнопка статистики
доступна в интерфейсе, а консоль содержит краткую диагностику без текста истории
и значений переменных. `release` предназначен для публичной сборки: он скрывает
кнопку статистики и обычные отладочные сообщения, сохраняя предупреждения и
ошибки.

Режим `release` можно принудительно включить параметром адреса, не изменяя
сценарий:

```text
index.html?mode=release
index.html?release
```

Обе формы регистронезависимы, применяют те же правила консоли, скрывают кнопку
статистики и записывают эффективное значение `release` в сценарную переменную
`mode`. Они не меняют стартовую сцену и правила автосохранения. URL может
повысить `debug` до `release`, но не понижает заданный в `[meta]` режим
`release`.

### `window`

Режим окна истории.

```text
window = vertical
window = auto
```

`vertical` используется по умолчанию и ориентирован на портретный экран 9:16.
Реализация ограничивает центральную область соотношением до 10:16 и сужает её
до фактического окна, поэтому интерфейс остаётся совместимым с экранами и
планшетами 9:16 и 10:16. `auto` растягивает фон, видео или 360°-слой на весь
доступный экран, но оставляет интерфейс, меню, диалог и кнопки в центральной
адаптивной области до 10:16. Если явно заданы `topSpacing`, `rightSpacing`,
`bottomSpacing` или `leftSpacing`, ручные отступы имеют приоритет.

### `bg360Quality`

Глобальный режим выбора normal/mobile для CSS-пакетов 360-фонов.

```text
bg360Quality = auto
bg360Quality = normal
bg360Quality = mobile
```

`normal` выбирает основной `*-360.css`, `mobile` — `*-360-mobile.css`, а `auto`
выбирает mobile только на уверенно определённом телефоне. Если CSS отсутствует
или повреждён, панорама не загружается: исполняемого JS-фолбэка нет. Если
параметр не задан, используется `normal`.

### `engine.optimized`

Режим подбора оптимизированных WebP-копий для обычных растровых изображений.

```text
engine.optimized = false
engine.optimized = true
engine.optimized = auto
```

`false` использует только пути, явно указанные в сценарии. `true` и `auto`
сначала пробуют соседние WebP-копии с суффиксами `--vnv-optimized` и
`--vnv-optimized-mobile`, а затем автоматически возвращаются к исходному файлу,
если оптимизированной копии нет. Если параметр не задан, используется `false`.

### `engine.loadsafe`

Режим безопасного восстановления автосохранения.

```text
engine.loadsafe = true
engine.loadsafe = false
```

По умолчанию `true`: автосохранение восстанавливается только для совместимой
версии текста истории, чтобы старый прогресс не переносился на уже изменённую
структуру сценария. `false` можно использовать только осознанно, когда нужно
разрешить восстановление даже после изменений текста истории.

### `engine.gameSandbox`

Режим изоляции HTML-мини-игр. Поддерживается только значение:

```text
engine.gameSandbox = strict
```

`strict` запускает игры с `sandbox="allow-scripts"`, скрывает referrer и не
разрешает игре читать DOM и хранилище родительской страницы, открывать окна или
перенаправлять страницу новеллы. Если параметр отсутствует, используется
`strict`. Значение `legacy` является ошибкой сценария; старые игры необходимо
перевести на протокол версии 2.

### `autosave`

Включает или отключает автоматическое локальное сохранение прогресса.

```text
autosave = true
autosave = false
```

Если параметр не задан, автосохранение включено. `false` удобно для коротких
тестов, когда каждый запуск должен начинаться с первой сцены.

При `projectId = demo-story` обычный слот имеет имя
`vn_engine_autosave_v1:project:demo-story`, а URL `?novel=intro` использует
`vn_engine_autosave_v1:project:demo-story:novel:intro`. Если параметра нет,
сохраняются legacy-имена `vn_engine_autosave_v1` и
`vn_engine_autosave_v1:novel:intro`.

После добавления `projectId` движок один раз копирует legacy-сохранение, только
если его версия, структура и fingerprint совпадают со сценарием до добавления
этой строки. Исходный legacy-слот остаётся на месте; чужой, неоднозначный или
повреждённый слот также не изменяется и не удаляется.

### `transition`

Глобальный визуальный переход при смене фона.

```text
transition = fade
transition = black
transition = white
transition = instant
transition = none
```

Переход можно переопределить для конкретной команды `bg` через
`transition=<тип>`.

### `transitionMs`

Длительность глобального перехода в миллисекундах.

```text
transitionMs = 180
```

Значение должно быть числом `>= 0`. Для отдельной команды `bg` можно указать
`transitionMs=<ms>`.

### Параметры интерфейса

Эти поля не меняют логику сценария, но управляют отображением:

```text
topSpacing = 500
bottomSpacing = 800
leftSpacing = 0
rightSpacing = 0
blurBackground = true
blurStrength = 50
blurBrightness = 0.9
blurOpacity = 0.95
```

Поддерживаемые поля:
- `topSpacing`
- `bottomSpacing`
- `leftSpacing`
- `rightSpacing`
- `blurBackground`
- `blurStrength`
- `blurBrightness`
- `blurOpacity`

## 🖼 Секция `[bg]`

Описывает фоновые изображения, видео-фоны и 360-панорамы.

Формат:

```text
[bg]
<bgId> file=<path>
```

Пример:

```text
[bg]
campusHall file=assets/backgrounds/bg_campus_hall.jpg
libraryEvening file=assets/backgrounds/bg_library_evening.jpg
wideCafe file=assets/backgrounds/cafe-wide.jpg scroll focusx=0.47 focusy=0.5 scale=1
labVideo file=assets/backgrounds/lab.mp4 fallbackimage=assets/backgrounds/lab.jpg volume=0.0
```

Использование в сцене:

```text
bg campusHall
```

Поддерживаемые параметры:

- `file` — обязательный путь к изображению, видео или CSS-пакету 360.
- `fallback`, `fallbackimage` или `poster` — изображение-заглушка для видео-фона.
- `volume` — громкость видео-фона от `0` до `1`; обычно для фона используют `0.0`.
- `scroll` — включает горизонтальное перетаскивание широкого изображения или видео.
- `focusx` и `focusy` — точка композиционного фокуса от `0` до `1` или слова `left`/`center`/`right`, `top`/`center`/`bottom`.
- `scale` — визуальное увеличение медиа; можно указать число больше `0` или имя переменной.
- `360`, `quality`, `focusz`, `fov`, `userfocus` — параметры 360-фона.

Эти же параметры можно переопределять в команде `bg`, если один и тот же ресурс
нужно показать с другим кадрированием в разных сценах.

Для панорамных изображений нужно указывать CSS-пакет, а не исходный растр;
360-видео по-прежнему может использовать `.mp4` или `.webm`:

```text
[bg]
campus360 file=assets/360/campus-360.css 360 quality=auto

[scene]
bg campus360 quality=mobile
```

`quality` принимает `auto`, `normal` или `mobile`. Если `quality` не задан или
равен `auto`, используется глобальный `bg360Quality` из `[meta]`. При итоговом
`mobile` движок загрузит `campus-360-mobile.css`. Пути к `*-360.js` и прямым
`.jpg/.png/.webp` в 360-фоне считаются ошибкой.

### `goto360`

Команда входит в 360-пространство, описанное в `story360.js`.

```text
goto360 korpusNight.174 entry=default
goto360 korpusNight 174 entry=fromIntro button="Выйти"
```

`story360.js` должен находиться рядом с `story.js` и задавать `window.STORY360`.
Файл сам описывает 360-панорамы через поле `file`; редактор создаёт служебные
`bgId` автоматически и не требует дублировать эти панорамы в секции `[bg]`
обычного сценария.

В корне `window.STORY360` обязательно числовое поле `version: 1`. Версия
принадлежит формату 360°-конфигурации, а не DSL файла `story.js`. Runtime и
аудитор отклоняют отсутствующую или неизвестную версию вместо автоматической
интерпретации по текущим правилам.

Файл является необязательным и выполняется в отдельном Web Worker. Основная
страница принимает только проверенную JSON-подобную копию `window.STORY360` без
функций, специальных прототипов, циклических ссылок и опасных ключей. Ошибка
`story360.js` отключает карту пространств, но не мешает запуску обычных сцен.

Проверка и создание копии завершаются внутри Worker до передачи через
`MessagePort`. Допускается не более 250 000 узлов с учётом каждого контейнера и
примитивного элемента массива, глубина не более 64, строка не длиннее 4 МиБ и не
более 16 МиБ строк суммарно. Массив, длина которого уже превышает оставшуюся квоту,
отклоняется до создания массива-копии.

CSS-пакет `*-360.css` подключается только во временный sandbox-iframe без
скриптов. Случайный CSP nonce разрешает единственный корневой `link`, поэтому
`@import` и загрузка ресурсов из CSS блокируются. Движок читает известные custom
properties, проверяет схему, MIME, base64, сигнатуру, размер и разрешение
изображения, создаёт Blob-текстуру и удаляет iframe. Стили пакета не подключаются
к странице новеллы.

Для normal и mobile действует единый верхний предел `20000 × 15000`, не более
`300 000 000` пикселей. Base64 ограничен 128 МиБ, бинарное изображение — 96 МиБ,
а число частей — 4096 при максимуме 32 КиБ на часть. Движок до запуска декодера
читает реальные размеры из заголовка PNG/JPEG/WebP и сверяет их с метаданными
пакета. Дополнительно действует меньший аппаратный предел `MAX_TEXTURE_SIZE`
текущего WebGL-устройства.

JS-пакеты изображений `*-360.js` не поддерживаются и никогда не выполняются
движком. Конвертер умеет лишь пассивно извлечь данные из старого пакета для
миграции в CSS. Импортированный в редактор JS-путь сохраняется как данные, но не
запускается; перед запуском истории его нужно заменить на `*-360.css`. Редактор
загружает превью основной панорамы только из CSS-пакета; прямой выбор JPEG, PNG
или WebP отключён. URL, абсолютные пути и выход через `..` в редакторе запрещены.

Редактор хранит изменения в рабочей копии. Кнопка «Сохранить версию в браузере»
создаёт явную контрольную точку, которая открывается после обновления страницы.
Более свежая аварийная копия записывается отдельно и восстанавливается только по
выбору пользователя. Скачивание `story360.js` формирует файл из рабочей копии,
но само по себе не меняет сохранённую в браузере версию.

При ручном редактировании ID пространства, панорамы и метки разрешены только
латинские буквы `A-Z`, `a-z` и цифры `0-9`. Старые импортированные ключи редактор
не переименовывает сам. В поле 360-перехода `P2` означает панораму `P2` текущего
пространства, а `B.P2` — панораму `P2` пространства `B`, независимо от текущего
пространства. Допускается не более одной точки; при экспорте явное пространство
записывается как `target: { type: "360", space: "B", panorama: "P2" }`.

У панорамы может быть необязательное строковое поле `comment`. Это авторская
заметка для навигации в редакторе: она показывается в списке как
`Space.Panorama "Комментарий"`, не участвует в переходах и игнорируется движком.
Если поле в редакторе пустое, `comment` в экспорт не добавляется.

Минимальный формат:

```js
window.STORY360 = {
  version: 1,
  spaces: {
    korpusNight: {
      panoramas: {
        "174": {
          comment: "Главный вход в корпус",
          file: "assets/360/korpusnight/174-360.css",
          entries: {
            default: { focusX: 0.2527, focusY: 0.5628 },
            from175: { focusX: 0.5080, focusY: 0.5000 }
          },
          marks: [
            {
              id: "to175",
              x: 0.5087,
              y: 0.4387,
              type: "walk",
              text: "К 175",
              target: { type: "360", panorama: "175", entry: "from174" }
            },
            {
              id: "exit",
              x: 0.2000,
              y: 0.5000,
              type: "walk",
              text: "",
              target: { type: "scene", scene: "scIntro01" }
            }
          ]
        }
      }
    }
  }
};
```

`entry` выбирает направление камеры при входе в панораму. Это заменяет схемы вида `focusx2/focusx3` и хранит направление движения прямо в переходе.
`text` у метки задаёт подпись на нижнем компасе 360; пустая строка или отсутствие поля означает, что подпись не выводится.

## 🎬 Секция `[video]`

Описывает полноэкранные сюжетные видео-вставки.

Формат:

```text
[video]
<videoId> file=<path> poster=<path> volume=<0..1>
```

Пример:


## 🎮 Секция `[game]`

Описывает мини-игры, доступные сценарию.

Формат:

```text
[game]
<gameId> file=<path> title="<title>" description="<description>" cover=<path>
```

Расширенный пример:

```text
[game]
coffeeRush file=assets/games/coffee_rush.html title="Coffee Rush" description="Лови заказы и избегай ошибок." cover=assets/games/coffee_rush.jpg
spaceDebris file=assets/games/space_debris.html title="Космические обломки" description="Проведи спутник через опасную зону." cover=assets/games/space_debris.jpg
```

Игра вызывается в сцене через команду `game`.

Поддерживаемые поля:

- `file` — обязательный путь к HTML-файлу мини-игры.
- `title` — человекочитаемое название для списка игр и графа ресурсов.
- `description` — короткое описание для встроенного списка игр.
- `cover` — изображение-превью; также принимаются алиасы `coverimage`, `thumbnail` и `logo`.
- `sandbox=strict` допускается как явная совместимая запись, но не меняет режим:
  все игры используют строгую изоляцию; любое другое значение считается ошибкой.

Данные конкретного запуска не хранятся в `[game]`: параметры вроде `difficulty`,
`targetScore` или `data` задаются в команде `game` и уходят в мини-игру через
сообщение `gameInit`.

## 🧮 Секция `[var]`

Описывает переменные сценария.

Формат:

```text
[var]
<varName> = <value>
```

Примеры:

```text
[var]
score = 0
resultGame = 0
playerName = "Alex"
isReady = true
```

Поддерживаемые типы:
- number
- string
- boolean

Переменные используются для:
- ветвления через `if`
- изменения состояния сценария
- хранения результата мини-игр

Имена переменных регистрозависимы: `Score` и `score` являются разными
переменными. Раздел `VARIABLES` в текстовой статистике группирует написания,
которые различаются только регистром, и показывает места их использования.
Такие группы часто означают опечатку, но движок не объединяет и не
переименовывает переменные автоматически.

Имя переменной должно начинаться с английской буквы или `_` и может содержать
только английские буквы, цифры и `_`. Проверка `Name rules` в разделе
`VARIABLES` выводит замечание для других символов, включая кириллицу, пробелы и
дефисы.

### `menu`

Показывает выбор игроку. Поддерживает два формата — старый (короткие переходы) и новый (блочные пункты с произвольными действиями).

По умолчанию пункты меню выводятся с автоматической нумерацией и заголовком `Выберите действие`. Чтобы явно включить номера для конкретного меню, используйте `menu numbered` или `menu numbered=true`; чтобы отключить номера, используйте `menu numbered=false` или `menu plain`. Для коротких вариантов можно включить плотные раскладки: `menu compact` делает кнопки по ширине текста с обычным переносом, а `menu fit` балансирует строки и растягивает кнопки пропорционально их естественной ширине. Плотные раскладки всегда скрывают номера, даже если вместе с ними указан `numbered`. Заголовок можно заменить через `title="..."`; пустой `title=""` скрывает заголовок. Любая неизвестная опция после `menu` считается ошибкой.

#### Старый формат — только переходы

```text
menu
"Вариант 1" -> scene_a
"Вариант 2" -> scene_b
```

`end` не нужен — меню автоматически закрывается на следующей не-меню команде (`show`, `set`, `goto`, `bg`, `if`, новый `menu` и т.п.), на следующем `scene xxx` или в конце файла.

Пример:

```text
menu numbered=false
"Зайти в кафе" -> branch_cafe_01
"Пойти в лабораторию" -> branch_lab_01
```

Компактный режим:

```text
menu compact title=""
"Да" -> scYes
"Нет" -> scNo
"Позже" -> scLater
```

Сбалансированный плотный режим:

```text
menu fit title=""
"Да" -> scYes
"Нет" -> scNo
"Позже" -> scLater
"Собрать" -> scCollect
```

Свой заголовок:

```text
menu title="Куда пойти?"
"Кафе" -> branch_cafe_01
"Лаборатория" -> branch_lab_01
```

#### Новый формат — `choice` + `end`

Если пункту нужно выполнить несколько действий (изменить переменные, показать реплику, потом перейти на сцену), используется ключевое слово `choice`. В этом режиме `end` обязателен.

```text
menu
choice "Атака"
  set hits = hits + 1
  anna: "В бой!"
  goto scAttack
choice "Бежать" -> scRun
choice "Поговорить"
  igor: "Постой!"
  set hostility = hostility - 1
  goto scTalk
end
```

Краткую (`choice "..." -> scene`) и полную (`choice "..."` + блок действий) форму можно свободно смешивать **внутри одного нового меню** — обе используют ключевое слово `choice`, поэтому это не считается смешением форматов:

```text
menu
choice "Простой переход" -> scA
choice "С действиями"
  set x = x + 1
  goto scB
choice "Снова короткий" -> scC
end
```

Внутри `choice` можно использовать любые сценарные команды, включая блочный `if/elif/else/end`:

```text
menu
choice "Атака"
  if hasSword
    set damage = 20
    goto scWin
  else
    goto scLose
  end
choice "Бежать" -> scRun
end
```

#### Правила

- Ограничения форматов действуют **только в рамках одного блока `menu`**. В одной истории (и даже в одной сцене) разные `menu` могут использовать разные форматы — старый и новый независимо.
- Внутри **одного** `menu` смешивать форматы нельзя: если хотя бы один пункт начинается с `choice`, все остальные тоже должны быть с `choice`.
- В старом формате `end` писать **нельзя**.
- В новом формате `end` **обязателен**.
- Внутри блока `choice` строки в кавычках без `->` трактуются как авторский текст (нарратор) — пункт меню всегда явно начинается со слова `choice`.

Пример смешения двух меню разного формата в одной сцене:

```text
scene scExample

menu
"Старый вариант 1" -> scA
"Старый вариант 2" -> scB

show anna welcome

menu
choice "Новый вариант 1"
  set x = x + 1
  goto scC
choice "Новый вариант 2" -> scD
end
```

## 🔀 Логика и ветвление

Сценарий может изменять ход повествования через:
- `menu`
- `goto`
- `if`
- значения переменных
- результаты мини-игр

Пример:

```text
[var]
coffeeResult = 0

[scene]
scene cafe_scene
game gameCoffeeRush difficulty=3 result=coffeeResult

if coffeeResult == 1 -> cafeGood
```

## ❌ Типичные ошибки

- `startScene` указывает на несуществующую сцену
- `goto` ведёт в несуществующую сцену
- `if` ведёт в несуществующую сцену
- игра вызывается по `gameId`, которого нет в `[game]`
- используются разные стили записи без необходимости
- идентификаторы трудно читать или они непоследовательны
- сцена слишком длинная и содержит слишком много несвязанных действий
- переменная используется в логике, но не объявлена заранее

## ✅ Минимальный чек-лист сценария

- есть секция `[meta]`
- указан `startScene`
- стартовая сцена существует
- все сцены имеют уникальные идентификаторы
- все переходы ведут в существующие сцены
- все используемые `bg`, `char`, `audio`, `video`, `game` объявлены в соответствующих секциях
- все переменные, используемые в логике, объявлены в `[var]`
- сценарий читаем и человеком, и ИИ
