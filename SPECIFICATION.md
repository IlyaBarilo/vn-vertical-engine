# 🎮 VN Engine — Спецификация сценария и мини-игр (для авторов и нейросетей)

Документ одновременно:
- 📖 удобен для человека
- 🤖 строг для нейросети

Этот файл является:
- полной спецификацией языка сценариев
- контрактом для интеграции мини-игр
- источником истины для генерации игр через нейросети

Используйте его как:
- руководство для написания сценариев
- инструкцию для разработки мини-игр
- промпт для генерации игр

В спецификации описано:
- структура сценария (`[meta]`, `[scene]`, `[game]` и др.)
- синтаксис команд (`scene`, `bg`, `if`, `game`)
- работа с переменными
- интеграция мини-игр через iframe
- строгий контракт для разработки игр (подходит для нейросетей)

Рекомендуется:
- авторам новелл — перед написанием сценария  
- разработчикам мини-игр — перед реализацией игры

---

# 📁 ОБЩАЯ СТРУКТУРА

Сценарий (`story.js`) состоит из секций:

* [meta] — метаданные сценария
* [bg] — список фоновых изображений
* [char] — описание персонажей
* [audio] — аудио ресурсы
* [game] — реестр мини-игр
* [var] — переменные сценария
* [scene] — сцены и логика

---

# 🔧 СЕКЦИИ

### [meta] — метаданные сценария

Определяет общие параметры новеллы.

```text
[meta]
title: Название
startScene: intro
```

Формат:
```text
<key>: <value>
```

где:
- `<key>` — имя параметра
- `<value>` — значение параметра


#### Поддерживаемые параметры

##### title

```text
title: Название
```

- описание: название новеллы (отображается в интерфейсе)

---

##### startScene

```text
startScene: intro
```

- описание: идентификатор стартовой сцены  
- должен соответствовать `scene <sceneId>`

---

#### Правила

- секция `[meta]` должна быть объявлена один раз
- параметры задаются в формате `<key>: <value>`
- неизвестные параметры игнорируются





---

### [bg] — список фоновых изображений

```text
[bg]
hall = assets/backgrounds/bg_hall.jpg
```

Формат:
```text
<bgId> = <imagePath>
```

где:
- `<bgId>` — идентификатор фона
- `<imagePath>` — путь к изображению

Использование:
```text
bg hall
```

---

### [char] — описание персонажей

```text
[char]
anna image neutral = assets/characters/anna.png
anna name = "Анна"
anna color = #0F0
```

Форматы:

```text
<charId> image <state> = <imagePath>
<charId> name = <string>
<charId> color = <color>
```

где:
- `<charId>` — идентификатор персонажа
- `<state>` — состояние (эмоция)
- `<imagePath>` — путь к изображению


---

### [audio] — аудио ресурсы
```text
[audio]
bgmDay = assets/audio/day.mp3
```

Формат:
```text
<audioId> = <audioPath>
```

---

### [game] — реестр мини-игр

```text
[game]
coffeeRush = assets/minigames/coffee_rush.html
```

Формат:
```text
<gameId> = <htmlPath>
```

где:
- `<gameId>` — идентификатор игры. Должен быть уникальным в рамках сценария
- `<htmlPath>` — путь к HTML файлу

---

### [var]

```text
[var]
score = 0
```

Формат:
```text
<varName> = <value>
```

где:
- `<varName>` — имя переменной
- `<value>` — начальное значение:
  - number
  - string
  - boolean

Особенности:
- переменные используются в логике (`if`, `set`)
- могут изменяться во время выполнения
- могут хранить результат мини-игр

# 🎬 СЦЕНЫ

```text
scene <sceneId>
```

Пример:
```text
scene intro

bg hall
show anna neutral

anna: "Привет!"
```

где:
- `<sceneId>` — уникальный идентификатор сцены

Сцена содержит:
- команды управления (`bg`, `show`, `game`, `goto`)
- диалоги
- переходы

---

# 🔀 ЛОГИКА

## Переход

```text
goto <sceneId>
```

где:
- `<sceneId>` — идентификатор сцены назначения

## Условие

```text
if <expression> -> <sceneId>
```

Пример:
```text
if score == 1 -> good
if score == 0 -> bad
```

где:
- `<expression>` — логическое выражение
- `<sceneId>` — сцена перехода

Поддерживается:
- `==`, `!=`, `>`, `<`, `>=`, `<=`

# 🎮 МИНИ-ИГРЫ


## 📌 Общая идея

Мини-игра — это отдельный HTML-файл, который:
- загружается в iframe
- изолирована от движка
- получает параметры от движка
- возвращает результат

---

## ▶️ Запуск игры в сценарии

game coffeeRush difficulty=3 result=resultCoffee

### Параметры

| Параметр | Обязательный | Описание |
|--------|------------|--------|
| gameId | ✅ | имя игры из [game], например, coffeeRush |
| difficulty | ❌ | сложность (обычно в диапазоне 1–5), по умолчанию 3 |
| result | ✅ | имя переменной для результата, например, resultCoffee |
| любые другие | ❌ | передаются в игру |

---

## 📥 ВХОД В ИГРУ

Игра получает:

```json
{
  "type": "gameInit",
  "gameId": "coffeeRush",
  "difficulty": 3
}
```

Дополнительно:
- могут передаваться любые другие параметры (например: speed, time, targetScore)
- игра должна игнорировать неизвестные параметры

---

## ❗ СТРОГИЙ КОНТРАКТ (ОБЯЗАТЕЛЬНО)

Движок и игра взаимодействуют через `postMessage`.

Формат:
- вход: `gameInit`
- выход: `gameResult`

Игра ОБЯЗАНА:

1. Слушать message type="gameInit"
2. Использовать difficulty
3. При завершении ОБЯЗАНА отправить:

parent.postMessage({
  type: "gameResult",
  result: resultValue
}, "*");

4. Отправить РОВНО 1 раз (повторная отправка запрещена)
5. НЕ перезагружать страницу
6. НЕ менять location
7. Поле result ОБЯЗАТЕЛЬНО должно быть числом
8. Если result отсутствует → считается 0
9. После отправки результата игра должна прекратить взаимодействие с пользователем

---

## 📊 RESULT

- тип: integer
- 0 → fail
- 1 → success
- допускаются другие числа
- используется в условиях сценария (`if`)

---

## 🎯 В СЦЕНАРИИ

game coffeeRush difficulty=3 result=resultCoffee

if resultCoffee == 1 -> good
if resultCoffee == 0 -> bad

---

## ⚙️ ПАРАМЕТРЫ

Любые параметры разрешены:

game coffeeRush difficulty=4 speed=2 result=resultCoffee

Игра должна игнорировать неизвестные поля.

## 🚫 АНТИ-ПАТТЕРНЫ ДЛЯ ИГР

Следующие подходы считаются ошибками проектирования и должны избегаться:

### ❌ Управление и UX

- размещение элементов управления только в верхней части экрана  
- размещение элементов управления у самого нижнего края экрана  
- мелкие кнопки, по которым сложно попасть пальцем  
- разнесённые по экрану кнопки управления (нет группировки)  
- отсутствие визуальной обратной связи при нажатии  

---

### ❌ Игровой процесс

- длительное ожидание без действий (более 1–2 секунд без интерактива)
- слишком длинная игра (рекомендуется ≤ 60 секунд)
- отсутствие понятной цели (игрок не понимает, что делать)
- резкое начало без объяснения (нет визуального или игрового контекста)

---

### ❌ Интеграция с движком

- игра не отправляет `gameResult`  
- отправляет `gameResult` несколько раз  
- отправляет `gameResult` с неверным форматом (не число)  
- использует асинхронную загрузку перед стартом игры  
- зависит от внешних ресурсов (API, CDN)  

---

### ❌ Технические ошибки

- использование `alert`, `confirm`, `prompt` как основного UI  
- блокирующие операции, зависания  
- необходимость скролла внутри игры  
- фиксированный layout, не адаптированный под вертикальный экран  
- элементы выходят за пределы экрана  

---

### ❌ Поведение после завершения

- игра продолжается после отправки результата  
- пользователь может продолжать нажимать кнопки после завершения  
- отсутствует визуальный сигнал окончания игры  

---

### 🧠 Итог

Если игра содержит один или несколько пунктов выше — она считается реализованной некорректно и может работать нестабильно в рамках движка.


## ⚠️ ДОСРОЧНОЕ ЗАВЕРШЕНИЕ

При досрочном завершении (выход, ошибка, прерывание) игра должна отправить:

parent.postMessage({
  type: "gameResult",
  result: 0
}, "*");

---

## 🎮 UX

- игра должна запускаться сразу после получения параметров
- задержка перед началом игры не должна превышать 500 мс
- управление должно поддерживать:
  - touch
  - mouse
- интерфейс должен быть оптимизирован под вертикальную ориентацию экрана

---

### 📱 Расположение элементов управления

- элементы управления не должны располагаться только в верхней или нижней части экрана (зоны, куда сложно дотянуться на мобильных устройствах)

- рекомендуется размещать элементы управления:
  - в центральной части экрана
  - справа или слева от центра
  - либо по центру, если это не мешает игровому процессу

---

### 🎛 Группировка и перемещение

- элементы управления должны быть сгруппированы:
  - компактно
  - в одном блоке

- рекомендуется использовать перемещаемую панель управления:
  - панель должна иметь область (например, "ручку" или "ярлык") для перетаскивания
  - пользователь должен иметь возможность перемещать панель в удобное место на экране

---

### 🕹 Тип управления

- для управления направлением рекомендуется использовать круговой контрол (virtual joystick), а не отдельные кнопки

- круговой контрол:
  - представляет собой область (обычно круг), в которой пользователь задаёт направление движением пальца
  - обеспечивает плавное и естественное управление
  - должен поддерживать непрерывное направление (не только 4 стороны)

---

### ❌ Не рекомендуется

- использовать отдельные кнопки:
  - "вверх / вниз / влево / вправо"
- размещать кнопки управления разнесённо по экрану

---

### ✅ Допустимые исключения

- кнопки допустимы, если:
  - управление дискретное (например: выбор, прыжок, действие)
  - механика не требует направления движения
