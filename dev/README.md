# Автоматические тесты движка

Автотесты защищают код движка от регрессий и не заменяют встроенную проверку
конкретной новеллы в статистике и графах. Автор истории продолжает пользоваться
инструментами внутри интерфейса, а разработчик движка и Codex запускают тесты
после изменения исходного кода.

## Граница публичной документации

Этот файл намеренно хранится в Git: он содержит только воспроизводимые команды,
назначение тестов и правила разработки. Здесь не должно быть реальных адресов и
настроек VPS/киоска, сведений о закрытой оболочке, учётных данных, ключей или
неопубликованных отчётов об уязвимостях. Пароли, токены и приватные ключи нельзя
хранить в репозитории.

Версии, лицензии и контрольные суммы поставляемых библиотек не являются
секретами: сами файлы уже опубликованы и эти сведения нужны для законного и
воспроизводимого обновления зависимостей.

## Требования

- Node.js 22 или новее;
- локальная копия Git-репозитория;
- для основных Node-тестов установка npm-пакетов и подключение к сети не требуются;
- для браузерных E2E-тестов один раз нужны `npm.cmd --prefix dev ci` и установка Chromium.

Тесты и Node.js не входят в пользовательский runtime движка и не нужны для
запуска готовой новеллы.

## Запуск

Все команды ниже выполняются из корня репозитория. Полная проверка:

```powershell
node --test
```

Все проверки `story-loader.js`:

```powershell
npm.cmd --prefix dev run test:parser
```

Метаданные и диагностика ошибок:

```powershell
npm.cmd --prefix dev run test:meta
```

Команды сцен, переходы, условия и меню:

```powershell
npm.cmd --prefix dev run test:scenes
```

Переменные, синтаксис и runtime-вычисление выражений:

```powershell
npm.cmd --prefix dev run test:variables
```

Объявления и параметры синтетических медиа:

```powershell
npm.cmd --prefix dev run test:assets
```

Команды `bg360marks`, `walk360` и `goto360`:

```powershell
npm.cmd --prefix dev run test:360
```

Счётчики встроенной статистики загрузчика:

```powershell
npm.cmd --prefix dev run test:stats
```

UI-схема, диапазоны и URL-параметры отступов:

```powershell
npm.cmd --prefix dev run test:ui
```

Режимы консоли, тяжёлые трассировки и защита диагностических данных:

```powershell
npm.cmd --prefix dev run test:logs
```

Протокол мини-игр, состав релиза, ссылки и формы сообщества:

```powershell
npm.cmd --prefix dev run test:protocol
npm.cmd --prefix dev run test:release
npm.cmd --prefix dev run test:links
npm.cmd --prefix dev run test:community
```

В командах для PowerShell используется `npm.cmd`, поэтому запрет запуска
`npm.ps1` не мешает проверкам. Для отдельного файла также можно выполнить
`node --test dev/tests/<имя>.test.mjs`.

Успешный запуск завершается кодом `0`. Любой проваленный тест возвращает
ненулевой код, поэтому GitHub Actions и Codex могут автоматически остановить
проверку и показать имя нарушенного контракта.

## Браузерные E2E-тесты

Первичная установка developer-зависимостей и Chromium:

```powershell
npm.cmd --prefix dev ci
npm.cmd --prefix dev run browser:install
```

Запуск в фоновом Chromium:

```powershell
npm.cmd --prefix dev run test:e2e
```

Запуск с видимым окном браузера для ручной диагностики:

```powershell
npm.cmd --prefix dev run test:e2e:headed
```

## Диагностика консоли

`mode = debug` оставляет краткие сообщения с идентификаторами сцены, индексом и
типом действия. `mode = release` отключает обычную диагностику, но не скрывает
реальные `console.warn` и `console.error`.

Для воспроизведения конкретной ошибки добавьте к адресу единый параметр
`Debug`. Имя параметра читается без учёта регистра, но в документации используется
форма с заглавной `D`:

```text
index.html?Debug=autosave
index.html?Debug=visual,character
index.html?mode=release&Debug=runtime
index.html?Debug=all
```

Доступные категории: `runtime`, `loader`, `autosave`, `visual`, `character`,
`360`, `assets`, `graph` и `audio`. Несколько категорий разделяются запятыми,
пробелами или точкой с запятой. `all` включает их одновременно.

Диагностика не должна раскрывать содержимое новеллы и игровые данные. Перед
отправкой журнала в Codex всё равно просмотрите его. API-ключи, пароли и токены
нельзя хранить в клиентских файлах проекта: они доступны пользователю
независимо от режима консоли.

Браузерные тесты используют только синтетические сценарии и не читают локальные
пользовательские истории, ассеты, игры или лицензионный ключ.

## Что проверяется сейчас

- парсер `[meta]`, DSL-команды, сцены, переходы, меню, условия и переменные;
- expression runtime, UI-параметры, медиа и команды 360°;
- полный разбор `story-example.js` и обратную совместимость legacy-синтаксиса;
- режимы консоли, автосохранение и разделение проектов по `projectId`;
- протокол и iframe-режимы мини-игр, а также работу авторских инструментов;
- состав, контрольные суммы и браузерный smoke собранного релизного ZIP;
- ссылки документации, формы сообщества и основные сценарии настоящего интерфейса.

Тесты используют синтетические данные. Игнорируемые пользовательские сценарии,
локальные ассеты и игры авторов в автоматической проверке не участвуют.

## Правила расширения

- Каждое исправление ошибки парсера сопровождается регрессионным тестом.
- Ожидаемый результат меняется только вместе с осознанным изменением
  спецификации или обратной совместимости.
- Fixtures должны быть небольшими и проверять один понятный контракт.
- Тесты не должны обращаться к сети или зависеть от случайных локальных файлов.
- Перед завершением изменения движка выполняется полный `node --test`.

Браузерный набор намеренно проверяет устойчивые поведенческие контракты, а не
пиксельные снимки интерфейса. За его пределами остаются визуальное сравнение,
реальные медиа, WebGL-панорамы и файлы конкретной демо-новеллы: такие проверки
сильнее зависят от устройства и пользовательских материалов.

## GitHub Actions

Workflow `.github/workflows/tests.yml` запускает полный набор:

- после push в `main`;
- для pull request;
- вручную через `workflow_dispatch`.

Job `test` выполняет автономные Node-тесты. Параллельный job `Browser E2E`
работает из каталога `dev/`: устанавливает developer-зависимости и Chromium,
затем запускает синтетические браузерные сценарии. При сбое его HTML-отчёт,
screenshot и trace сохраняются в GitHub Actions Artifacts на семь дней.

Release workflow повторяет тесты перед сборкой ZIP. Провал проверки не позволяет
собрать и загрузить релизные архивы.

### Безопасная ручная проверка ZIP

Workflow `Build ZIP for Release` можно запустить во вкладке **Actions** без
создания релиза и без изменения GitHub Pages:

1. Нажмите **Run workflow**.
2. В поле версии укажите временное имя, например `test-build`.
3. Оставьте `upload_to_release` и `deploy_pages` выключенными — это их безопасные значения по умолчанию.
4. После успешного завершения скачайте `release-zips-<run id>` в разделе **Artifacts** запуска.

Внутри artifact находятся полный и update-ZIP, а рядом с каждым архивом — файл
`.sha256`. Workflow повторно вычисляет контрольные суммы, проверяет целостность
обоих архивов, наличие runtime и пользовательских инструментов, отсутствие
developer-файлов, а также отсутствие ассетов и корневого сценария в
update-архиве. После этого полный ZIP распаковывается во временный каталог и
запускается в Chromium. Artifact хранится семь дней.

Локальная проверка скачанного архива по соседнему файлу SHA-256:

```powershell
node dev/scripts/release-checksums.mjs verify ".\vn-vertical-engine-test-build.zip.sha256"
```

При настоящей публикации отдельные `.sha256` загружаются для версионных и
`latest`-имён полного и update-архивов.

При подготовке полного архива `dev/scripts/copy-release-assets.mjs` копирует
разрешённые форматы из `assets/backgrounds`, `assets/characters`,
`assets/audio`, `assets/games` и `assets/video`, сохраняя вложенные каталоги и
отклоняя коллизии путей без учёта регистра. Команда
`npm.cmd --prefix dev run test:release` проверяет это на синтетических временных
файлах и не читает пользовательские ассеты проекта.

Локальная smoke-проверка уже собранного полного ZIP запускается командой:

```powershell
npm.cmd --prefix dev run test:release:smoke -- "..\vn-vertical-engine-test-build.zip"
```

Перед первым запуском установите developer-зависимости и Chromium командами из
раздела «Браузерные E2E-тесты». Smoke-тест сам распаковывает архив во временный
каталог и удаляет его после проверки. Он подаёт небольшой синтетический
`story.js`, поэтому пользовательские сценарии и ассеты не участвуют, но
`index.html`, CSS, библиотеки и JavaScript движка читаются только из ZIP.

Включайте `upload_to_release` или `deploy_pages` только для настоящей
публикации: эти параметры соответственно изменяют GitHub Release и демо на
GitHub Pages. При событии публикации релиза оба действия по-прежнему
выполняются автоматически.

Весь каталог `dev/` нужен только разработчику и GitHub Actions. Release workflow
не копирует его, браузеры или отчёты в пользовательские ZIP-архивы и завершает
сборку ошибкой, если `dev/` неожиданно появляется внутри архива.
