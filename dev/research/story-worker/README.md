# Исследование безопасной загрузки авторского JS, 2026-09-02

Статус: результаты опытов и направления доработки, без изменения режима runtime.

Задача: проверить новости Chrome и варианты загрузки `story.js`/`story360.js`
при обязательном автономном запуске. Авторский процесс должен оставаться
«изменил JS → сохранил → F5», без сервера, упаковки и повторного выбора файлов.
Действующее решение и условия возврата Worker описаны в
[архитектуре загрузчика](../../architecture/story-script-worker.md).

## Вывод

Среди проверенных вариантов не найден транспорт, который одновременно
автоматически читает соседний JS в актуальном Chrome через `file://` и
обеспечивает прежнюю задуманную изоляцию. Сохранённый Worker требует усиления
независимо от исправления транспорта: обнаружены обходы запрета сети и
вложенного импорта. Возвращать его простым переключением константы рано.

Обычные script остаются действующим решением совместимости. Они выполняют
доверенный авторский JS с правами страницы; валидатор проверяет результат,
но не предотвращает побочные действия уже выполненного кода.

## Что известно об изменениях Chrome

- В [Chrome 150](https://developer.chrome.com/release-notes/150) официально
  объявлено назначение непрозрачного origin Worker, созданным из `data:` URL.
  Это изменение изоляции от состояния создавшей страницы. Оно относится к
  `data:` Worker; загрузчик движка создаёт **Blob Worker**, поэтому объявление
  само по себе не объясняет его отказ.
- В [заметках Chrome 151](https://developer.chrome.com/release-notes/151) и
  [Chrome 152](https://developer.chrome.com/release-notes/152) не найдено
  прямого объявления о запрете `importScripts(file://...)` из Blob Worker.
  Это ограничение найденных публичных сведений, а не доказательство отсутствия
  соответствующего изменения в исходном коде браузера.
- Chrome 152 объявляет Connection Allowlists: ограничение конечных адресов
  через HTTP-заголовок ответа. Для автономного файла этот механизм не даёт
  требуемого способа чтения JS и не заменяет рассмотренный ниже CSP.
- [Обновление Stable от 1 сентября](https://chromereleases.googleblog.com/2026/09/stable-channel-update-for-desktop.html)
  выпускает 152.0.7977.75/.76 для Windows и macOS с исправлениями безопасности.
  Отдельная официальная Chrome for Testing 152.0.7977.75 тоже воспроизвела
  отказ локального импорта. Поэтому на это обновление как на исправление
  проекта рассчитывать нельзя.

Версия отдельной тестовой сборки и ссылка на неё взяты из
[официального списка Chrome for Testing](https://googlechromelabs.github.io/chrome-for-testing/last-known-good-versions-with-downloads.json).
Установленный Chrome и пользовательский профиль не обновлялись.

Различие между проверенными Chromium 151 и Chrome 152 подтверждено; конкретный
upstream-коммит, точная первая проблемная версия и намеренность изменения
не установлены. Возможные различия сборок и включения функций сохраняются.

## Среда и метод

Windows, Playwright Test 1.62.1, headless, отдельные временные профили:

| Проект тестов | Браузер |
| --- | --- |
| `chromium-bundled` | Полный Chromium 151.0.7922.34, не headless-shell |
| `chrome-installed` | Установленный Google Chrome 152.0.7977.64 |
| `chrome-testing` | Отдельная Chrome for Testing 152.0.7977.75 |
| `firefox-installed` | Установленный Firefox 155.0 |

Все исследуемые страницы открывались через настоящий `file://`. Локальные
запросы не подменялись. В Firefox задано
`use.launchOptions.firefoxUserPrefs["security.fileuri.strict_origin_policy"] = true`.
Флаги отключения web security или разрешения доступа между локальными файлами
не использовались. `--no-remote` отделяет тестовый процесс Firefox от уже
открытого пользовательского браузера; политику доступа этот параметр не ослабляет.

Скрипты синтетические, с коротким маркером, без данных проекта. Для проверки
сети использован зарезервированный адрес `vn-worker-probe.invalid` и перехват
Playwright с локальным ответом. Считались попытки запросов, дошедшие до
перехвата; данные во внешнюю сеть не отправлялись.

## Совместимость транспорта

«Успех» здесь означает только загрузку и получение маркера, а не доказанную
безопасность. Обе сборки Chrome 152 дали одинаковый результат в этой таблице.

| Вариант через `file://` | Chromium 151 | Chrome 152 .64/.75 | Firefox 155, строго |
| --- | --- | --- | --- |
| Blob Worker → `importScripts(file://story.js)` | Успех | `NetworkError` | Успех |
| Data Worker → `importScripts(file://story.js)` | Успех | `NetworkError` | `SecurityError` |
| `new Worker(file://worker.js)` | Отказ | Отказ | Отказ загрузки |
| Blob Worker → Blob URL, созданный страницей | Отказ | Отказ | Успех |
| Blob Worker → `importScripts(data:...)` | Успех | Успех | Успех |
| Module Worker из `data:` → `import(file://...)` | Отказ | Отказ | Отказ |
| Module Worker из `data:` → `import(data:...)` | Успех | Успех | Успех |
| File API → текст → `data:` в настоящем загрузчике | Успех | Успех | Успех |
| Строгий iframe `allow-scripts` → локальный script | Отказ | Отказ | Отказ |
| Локальный iframe с `allow-same-origin` → локальный script | Успех | Успех | Успех |

Дополнительные контрольные варианты:

- `.mjs` вместо `.js` и `credentials: "omit"` не устранили отказ Chrome 152.
- `.txt` с тем же JS отвергался; MIME/расширение — отдельный фактор.
- Blob **module** Worker в Chromium/Chrome завершался ошибкой до результата;
  в Firefox запускался, но также не импортировал локальный модуль.
- `fetch(file://..., {mode: "no-cors"})` из страницы возвращал `opaque`
  response с пустым доступным текстом во всех сборках. Это не чтение файла.
  Из Blob Worker Chrome 152 выдавал ошибку, Chromium 151 и Firefox — такой же
  непригодный для чтения opaque response.
- После F5 выбор `<input type="file">` сбрасывался в Chromium/Chrome.
  Firefox сохранил один выбранный файл в проверенном input. Это не гарантия
  автоматического доступа к соседнему пути во всех браузерах или сессиях.
- `showDirectoryPicker` доступен как функция в проверенных Chromium/Chrome,
  отсутствует в Firefox. Сохранение разрешения и чтение изменений через этот
  API в данном исследовании не проверялись; готовым переносимым решением он
  не признан.

## Что показали проверки безопасности

Результаты одинаковы во всех четырёх сборках, кроме небольших различий времени.

| Свойство сохранённого Worker | Наблюдение |
| --- | --- |
| Прямой DOM и `window.parent` | Недоступны |
| Обычные имена `fetch`, XHR и `Worker` | Скрыты, имеют тип `undefined` |
| Динамический `import("https://...")` | Один запрос дошёл до перехвата |
| Исходный `fetch` через прототипы | Восстановлен, один запрос дошёл до перехвата |
| Исходный `importScripts` через прототипы | Восстановлен, вложенный `data:` JS исполнился |
| Getter `indexedDB`/`caches` в прототипах | Найдены; успешные операции с хранилищем не проверялись |
| Поддельный обычный `self.postMessage` | Не принят вместо результата приватного канала |
| Бесконечный цикл | Worker завершён внешним таймаутом примерно за 10 секунд |
| Следующая загрузка после таймаута | Успешна |

Причина обхода API: собственное неизменяемое свойство `self.fetch = undefined`
скрывает имя, но не удаляет исходную функцию из `WorkerGlobalScope.prototype`.
Синтаксический `import()` вообще не является свойством `self`.

### Прототип с CSP

Тестовая HTML-страница разрешает доверенный загрузчик по nonce и наследует
ограничения в созданный Blob Worker:

```text
default-src 'none'; script-src 'nonce-researchOnly123' data:; worker-src blob:; connect-src 'none'; base-uri 'none'
```

При этой политике сценарий через `data:` успешно вернул результат, а запросы
через динамический импорт и восстановленный `fetch` не дошли до перехвата.
Проверены все четыре сборки. Для запрета внешних модулей нужен именно
`script-src`; одного `connect-src 'none'` недостаточно.

CSP не удаляет доступные ссылки на API, не решает чтение соседнего локального
JS и не делает разрешённый `data:` импорт запрещённым. Нужны усиление изоляции
API и проверка совместимости политики со всем движком. Пример выше относится
к минимальной исследовательской странице, а не является готовой политикой
для основного `index.html` с UI, медиа и библиотеками.

### Почему локальный iframe пока не заменяет Worker

С `sandbox="allow-scripts allow-same-origin"` отдельный локальный HTML смог
подключить сценарий; доступ к DOM родителя в проверенных `file://` сборках был
запрещён. Но тот же набор прав у **srcdoc** позволил изменить DOM родителя.
Нельзя переносить вывод об изоляции между этими двумя способами создания iframe.

Ограниченный цикл на 600 мс в локальном iframe задержал таймер родителя на
609–624 мс; такой же цикл в Worker оставил максимальный интервал таймера
около 21–23 мс. Следовательно, в проверенном запуске iframe блокировал основной
поток, и таймаут родителя не сможет вовремя прервать бесконечный цикл. Настоящий
бесконечный цикл испытывался только в Worker, который можно завершить извне.

## Что потребуется для возврата защиты

1. Найти совместимый транспорт исходного текста без изменения согласованного
   процесса редактирования либо отдельно согласовать иной процесс.
   `data:` работает как транспорт уже полученных байтов, но не выдаёт доступ
   к исходному файлу. File API и предварительная упаковка требуют этого решения.
2. Сохранить отдельный Worker, приватный порт, валидацию до передачи результата,
   квоты и принудительное завершение; не выполнять исходный JS в главной странице
   «для предварительного чтения».
3. Добавить браузерную политику запрета внешних скриптов и соединений и усилить
   ограничения API с учётом всех доступных прототипов/getter. Проверять реальные
   попытки побочных действий, а не только `typeof fetch`.
4. Повторить интеграционные проверки обоих авторских файлов, F5, переходов,
   перезапуска, ошибок и очистки ресурсов в установленных Chrome/Firefox.
   Совместимость под HTTP(S) проверять отдельно; текущие опыты посвящены `file://`.

## Повторение и результаты проверок

Из каталога `dev`, с уже установленными зависимостями:

```powershell
npx.cmd playwright test --config research/story-worker/playwright.config.mjs
```

Для дополнительной отдельно скачанной Chrome for Testing можно задать полный
путь к её `chrome.exe` в `VN_RESEARCH_CHROME_EXECUTABLE` и повторить команду.
Тесты ничего не скачивают и не обновляют автоматически. Для целевого повтора
можно задать `VN_RESEARCH_RUN_LABEL`, чтобы сохранить прежний полный JSON.

Каждый браузер выполняет восемь тестов с несколькими подвариантами. Полная
матрица из 32 сочетаний «тест × сборка» проверена успешно в завершённых прогонах;
ограничения транспорта записываются как наблюдения, а не ошибочно считаются
проходящей проверкой безопасности. Дополнительно повторена проверка прототипов
с CSP после её расширения. JSON сохраняется в игнорируемом
`dev/.playwright/story-worker-research/`; временные fixtures удаляются.

В нескольких прогонах Firefox не запустился до таймаута, включая запуск с
`--no-remote`. Полный повтор его восьми проверок прошёл, а заключительные
две проверки CSP успешно повторены вне песочницы Codex с той же строгой
политикой Firefox. Причина нестабильного старта отдельно не установлена.
Тестовая CSP
первоначально не разрешила loader по списку `file:` URL в Chrome; вариант с
nonce прошёл. Эти сбои тестового окружения не признаны дефектами сценария.

ESLint исследовательских `.mjs`, проверка ссылок документации и CRLF выполнены.
Полные Node- и продуктовые E2E-наборы повторно не запускались: runtime и его
режим не менялись. Релиз не собирался, `release-manifest.json` не пересоздавался.
