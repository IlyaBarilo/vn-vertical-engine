# Проверка границ HTML-мини-игр, 2026-09-02

Статус: исследование завершено; совместимые меры внедрены в runtime и тестер.
Ниже сохранено исходное воспроизведение, затем описано текущее поведение.

Повод: после проверки Worker сценариев уточнить, какие ограничения HTML-игр
действительно обеспечены браузером, а какие остаются требованиями к автору.
Использованы настоящие `engine/game-host.js` и `engine/game-protocol.js`,
скопированные в минимальную временную страницу. На этапе исследования новелла и
файлы игр не менялись; изменения после исследования перечислены отдельно.

## Среда

Открытие родителя и исходной игры через настоящий `file://`, без сервера:

- установленный Chrome 152.0.7977.64;
- полный Chromium 151.0.7922.34;
- установленный Firefox 155.0 с
  `security.fileuri.strict_origin_policy: true` в `launchOptions.firefoxUserPrefs`.

Проверки выполнялись вне песочницы Codex из-за ранее наблюдавшихся сбоев запуска
Firefox; браузерные ограничения безопасности не отключались. Адрес
`vn-game-probe.invalid` перехватывался Playwright с локальным ответом. Использованы
только синтетические маркеры. Реальный внешний сервер не получал запросы.

Число перехваченных запросов — наблюдение на уровне автоматизации браузера,
а не захват сетевых пакетов. В частности, перехват Firefox может предшествовать
окончательному решению CSP; он не доказывает, что запрос ушёл бы во внешнюю сеть.

## Что работает

Строгий `sandbox="allow-scripts"` не дал игре изменить DOM родителя во всех
трёх браузерах. Исходный код host сохраняет отсутствие `allow-same-origin`,
разрешений верхней навигации, popup, загрузок, форм и чувствительных устройств.
Проверки протокола отклоняют неверное окно, неверный идентификатор сессии и
повторное завершение. Эти свойства подтверждены соответствующими Node-тестами;
камера и другие устройства в исследовании не запрашивались.

Со штатным CSP внутри HTML запросы `fetch` и динамического `import()` не дошли
до перехвата. Без этого CSP оба запроса дошли до перехвата, хотя DOM родителя
остался недоступен. Сам host не проверяет CSP исходного HTML при запуске.

## Пропуски исходного runtime до усиления

### Собственная навигация и повторная выдача gameInit

У исходной игры был полный строгий CSP из спецификации, включая
`connect-src 'none'`, `frame-src 'none'` и `form-action 'none'`.
После получения начального `gameInit` игра выполнила эквивалент
`location.replace(...)` для собственного iframe.

Во всех трёх браузерах:

1. Родительская страница осталась на `file://`; ограничение верхней навигации
   не было снято.
2. В iframe открылся новый документ, предоставленный тестовым перехватом.
3. `game-host.js` повторно отправил ему `gameInit` с теми же параметрами и сессией.
4. Новый документ вернул `gameResult: 777`, который host принял.

Причина прежней повторной выдачи: обработчик `frame.onload` оставался активным на каждую
следующую загрузку. `contentWindow` — ссылка на окно iframe, сохраняющаяся при
смене документа; проверка `event.source` не доказывает, что отвечает исходный
HTML. Это не обход доступа к DOM родителя и не получение произвольных файлов ОС.
Активная игра и без навигации может выбрать собственный числовой результат,
поэтому протокол также не следует считать защитой от нечестного счёта.

Выбранное исправление: выдавать начальные данные один раз и прекращать сессию
при повторной загрузке с закрытием модалки и восстановлением новеллы. Простого
удаления повторной отправки недостаточно: нужно отозвать уже выданную сессию.
Такое поведение совместимо с прежним запретом менять `location` в спецификации.

### Пределы статического аудитора

В синтетической игре обращение было записано через составные имена свойств:
`self['loc' + 'ation']['re' + 'place'](...)`. Адрес получался через `atob` из
строки Base64, поэтому в исходнике также не было литерала внешнего URL.
`inspectMiniGameSource()` вернул пустой список замечаний.

Прямые записи навигации и сетевых API аудитор обнаруживает, но поиск шаблонов
не доказывает безопасность произвольного JavaScript. Добавление ещё одного
регулярного выражения не устраняет этот класс обходов. Аудитор остаётся полезной
проверкой формата, явных опасных конструкций и комплектности; результат без
замечаний не означает разрешение запускать заведомо недоверенный код.

### Нагрузка на поток

У строгой игры был ограниченный цикл длительностью 600 мс. Таймер родителя
с периодом 20 мс показал максимальный интервал:

| Браузер | Интервал таймера родителя |
| --- | ---: |
| Chrome 152 | 21 мс |
| Chromium 151 | 21 мс |
| Firefox 155 | 618 мс |

В проверенном Firefox строгий iframe блокировал родительский поток. Следовательно,
таймаут основного окна нельзя считать переносимым способом прервать бесконечный
цикл игры. Отсутствие задержки в Chrome относится к данной конфигурации изоляции
процессов и не создаёт общего контракта для всех браузеров и устройств.
Бесконечный цикл в iframe не запускался.

## Проверенный дополнительный барьер

В минимальный родитель добавлен экспериментальный meta CSP:

```text
frame-src file: blob: data:
```

В Chrome и Chromium переход на внешний адрес не дошёл до перехвата. В Firefox
перехват увидел запрос документа, но новый документ не получил `gameInit` и его
результат не был принят. Поэтому по этому опыту нельзя обещать одинаковое
предотвращение исходящих запросов во всех браузерах.

Для внедрения в `index.html` добавлен `'self'`, сохраняющий свой origin при
HTTP(S). Проверка совместимости включает CSS-панорамы, сюжетную игру, статистику,
URL-запуск и настоящий `file://`. Политика родителя не заменяет CSP самой игры:
она не превращает произвольные API её документа в запрещённые.

Разделение между sandbox, вложенными ресурсами и навигацией описано в
[MDN об iframe](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe)
и [спецификации CSP](https://www.w3.org/TR/CSP/).

## Внедрённая защита

1. `engine/game-host.js` отправляет `gameInit` только после первого `load` явного
   запуска. Следующий `load` отзывает сессию до вызова UI, очищает iframe и
   запрещает поздний результат. Это действует и после результата URL-игры.
   Для каждого явного запуска создаётся новый iframe с URL и обработчиком до
   вставки в DOM. Иначе в установленном Chrome запоздалый `load` промежуточного
   `about:blank` при перезапуске иногда ошибочно останавливал исправную игру.
   Новый элемент отделяет документы и события разных запусков; ссылки обработчиков
   клавиатуры обновляются вместе с ним. Такой же приём применён в тестере.
   Модалка и её геометрия подготавливаются до вставки. Дополнительно Coffee Rush
   ждёт следующий кадр при нулевом начальном viewport, сохраняя прежний масштаб:
   одной подготовки геометрии оказалось недостаточно для стабильного запуска в
   Chrome. Повторная проверка включает видимую кнопку и после перезапуска.
2. Сюжет получает `0`, как при ручном закрытии; статистика возвращает каталог без
   продвижения сюжета; URL-запуск показывает сообщение до ручного перезапуска.
3. `index.html` применяет `frame-src 'self' file: blob: data:` до загрузки ресурсов.
   Локальные игры, свой HTTP(S) origin и служебные iframe панорам сохраняются.
4. Тестер отзывает сессию при навигации как URL, так и локального `srcdoc`,
   отменяет прежний отложенный init и запрещает ручной init до явной загрузки.
   Штатные загрузка и повторная отправка init текущему документу доступны.
5. [Спецификация игр](../../../docs/specs/spec-game.md) уточняет один документ на
   запуск, сброс состояния для «Ещё раз», запрет секретов в параметрах и границы
   защиты. Версия остаётся `2`; формат сообщений и строгий sandbox не меняются.

Регрессии проверяют продолжение сюжета, каталог, URL-перезапуск, тестер URL/srcdoc,
блокировку внешнего документа и запуск с перезапуском всех восьми встроенных игр.
Это проверка инициализации и UI, а не полное прохождение каждой игры.

Попутно исправлено прежнее исключение `fullIntroText is not defined` в
`interactive-screen-benchmark.html`: список инструкций теперь сохраняется перед
передачей в адаптивную карточку. Ошибка присутствовала в HEAD до усиления защиты.
У `board-under-voltage.html` видимые слои абсолютные, поэтому проверяется canvas,
а не высота `body`. Chromium сам запрещает локальный `location.reload()` из
непрозрачного origin; для проверки отзыва сессии через `file://` используется
разрешённый переход на `about:blank`, через HTTP проверяется также настоящий reload.

При проверке ввода обнаружились особенности автоматизации: Firefox BiDi иногда
возвращал `null` для `boundingBox` видимой кнопки строгого iframe, а масштабированный
предпросмотр тестера требовал прокрутки и пересчёта координат. Общий тестовый helper
читает прямоугольники через DOM, учитывает масштаб и отправляет настоящий клик
мышью. Это проверяет возврат результата после блокировки и повторного запуска;
полное прохождение и touch-управление всех игр этим не покрываются.

## Что отложено и почему

- Полный запрет сети произвольному HTML: родительский `frame-src` ограничивает
  документы, но не все API игры. Её собственный CSP и проверка кода остаются
  обязательными. Для Firefox не заявляется блокировка навигационного запроса
  до отправки в сеть; наблюдение перехвата этого не доказывает.
- Принудительное завершение зависшей игры таймером родителя: Firefox может
  задержать и этот таймер. Нужен внешний процесс с контролем CPU/памяти.
- CSP origin-allowlist в тестере: общий `'self'` нарушил бы существующую явную
  загрузку произвольного URL. Защита повторной инициализации внедрена, но тестер
  не становится безопасной средой для заведомо враждебного файла.
- Полная идентификация исходного документа: `load` обнаруживает завершившуюся
  повторную загрузку, но не доказывает отсутствие редиректа до первого load или
  намеренной передачи игрой уже известных ей параметров. Секреты в init запрещены.

Не следует трактовать прохождение текстового аудитора как доказательство
отсутствия побочных действий, зависания или исчерпания памяти.

Более сильные гарантии для произвольного враждебного HTML требуют отдельной
границы исполнения и контроля сети. Текущий автономный браузерный runtime таких
гарантий не предоставляет. Обычные проверенные игры могут продолжать использовать
нынешний формат; сам по себе HTML не означает пассивное содержимое.

## Повторение и проверки

Из каталога `dev`:

```powershell
npx.cmd playwright test --config research/html-games/playwright.config.mjs
```

На исходном runtime пройдены девять исследовательских тестов: три опыта в трёх браузерах. Обнаруженные
пропуски записаны как наблюдения; зелёный исследовательский прогон не означает,
что эти действия предотвращены. JSON находится в игнорируемом
`dev/.playwright/html-game-research/`.

Этот исследовательский тест копирует текущий host, поэтому после усиления его
наблюдения закономерно отличаются от исходных. Защитные ожидания закреплены в
`dev/tests/game-host.test.mjs`, `dev/tests/e2e/engine.spec.mjs` и
`dev/tests/e2e/local-game-security.spec.mjs`.

Продуктовые проверки на установленных Chrome/Firefox и полном Chromium можно
повторить из `dev`:

```powershell
npx.cmd playwright test --config research/html-games/runtime.config.mjs tests/e2e/local-game-security.spec.mjs
```

При выпуске сборки `release-manifest.json` создаётся штатным процессом
`.github/workflows/release-candidate.yml`; исходный каталог не содержит готового
релизного manifest, вручную подменять в нём хеши не нужно.

### Результаты усиления

- Полный Node-набор: 392 теста прошли. Полный продуктовый E2E-набор Chromium/Firefox:
  202 прошли, два штатно пропущены из-за пользовательского `story.js` в рабочей
  копии. Проверены в том числе CSS-панорамы normal/mobile через file/HTTP,
  переходы, перезапуск, очистка временных iframe и остановка пустого Audio.
- После окончательных исправлений жизненного цикла повторены 47 связанных
  Node-тестов: host, протокол, безопасность содержимого, аудитор и ссылки; все прошли.
- Финальный прогон в Chrome 152.0.7977.64, полном Chromium 151.0.7922.34 и Firefox
  155.0: 18 проверок прошли. Это сюжет, статистика, URL-режим, тестер URL/srcdoc
  и настоящий file://, включая реальные клики и восстановление после блокировки.
- Coffee Rush с проверкой видимой кнопки после перезапуска прошёл девять тестов:
  по три повтора в каждом из этих браузеров. Остальные семь встроенных игр и
  блокировка внешнего документа ранее прошли в той же браузерной матрице.
- ESLint и проверка типов прошли; окончания строк изменённых файлов — CRLF.

Полные наборы после последних локальных исправлений не повторялись: повторены
обнаружившие ошибки проверки и ближайшие регрессии. Релизный архив не выпускался.
